[1] 한 줄 요약
a27 전체 점검(code_audit_fix_a27_2026-08-20.md)에서 나온 항목 중 "설치 경로 이전(5번)" 을 뺀 전부를 고쳤다.
핵심: ① config.backup.json 유출 차단 ② 치킨 감지 재설계(페이드·오버레이에 강하게) + 치킨 수동 토글 ③ 카드 수정을
버튼 방식으로 교체(수정 후 한 번 더 전송) ④ 스팀 대기열 경로가 delay 를 무시하던 문제 ⑤ 전송 결과를 실제 결과대로 표시
⑥ 설정 즉시 저장 ⑦ 스팀 모드에서도 F9 유지 ⑧ 토큰 파일 원자 쓰기·갱신 실패 시 무효화 ⑨ 중복 전송 방지.
OCR 숫자 인식 코드는 무변경. 회귀 52/52 (치킨 판정 정답 52장 추가해서도 52/52).

[2] 큰 그림
- 배포 파이프라인(a26)·핫픽스(a27)가 실기에서 통과했으므로(깃허브 Actions 초록, 설치판 동작), 이번엔 "기능이 의도대로 도는가" 를 고치는 회차.
- 곡천님 결정: 수정 양식(오류값 상쇄 → 정답, 2회 전송)은 치지직 미션의 음수 허용 여부를 테스트한 뒤. 이번엔 수정된 값만 한 번 더 전송.
- 다음: a29 = LOCALAPPDATA 이전 + 비관리자 설치 + 언인스톨 정리. 그 뒤 OCR 게이트·인원 감지 교체, UI 통일.

[3] 핵심 결정과 이유

3-1. 치킨 감지 재설계 (_detect_rank_state)
   - 문제(실측): 노란 픽셀 "개수" 로 판정해서 결과창 페이드 중엔 치킨을 놓치고(+1000 만 빠짐), 채팅 오버레이가 겹치면 #20 을 치킨으로 오판(회귀 캡처 20260421050652).
   - 새 방식: 채도/명도 문턱을 낮추고(S 120→80, V 150→90) '#' 글자 뒤 첫 숫자 덩어리의 오른쪽 끝 x 로 판정.
     1080p 기준 실측: '#'=x34~78, '1'=x84~111, '2'~'9'=x85~117, 두 자리면 x118 이후 덩어리 추가. '#7' 처럼 7 이 '#' 에 붙는 경우는 한 덩어리(x34~115) → 비치킨.
   - 판정 불가(None): '#' 이 안 보이면(순위 미표시·가림). 화면 캡처 모드면 0.4초 뒤 한 번 재캡처해서 다시 본다. 그래도 None 이면 비치킨으로 두고 UI 에 "순위를 읽지 못했어요 — 치킨이면 🍗" 안내 + 칩 강조.
   - 검증: 테스터 QHD 102장(치킨 10) 오판 0, 인게임 17장 치킨 오판 0, 회귀 53장 True 5(전부 실제 #1 확인) / None 4(오버레이가 순위를 완전히 덮은 프레임) / False 43. a25 의 FP 1건 해소.
   - 회귀 테스트에 chicken 정답(truth.json "chicken") 추가. run_regression.py 가 _detect_rank_state 도 AST 로 추출해 비교한다.
   - 기각: 템플릿 매칭으로 '1' 글자 인식 — 글꼴·스케일 변형에 더 약하고, 현재 기하 규칙이 171장에서 오판 0 이라 과잉.

3-2. 치킨 수동 토글 (set_last_is_chicken) + 수정 패널 (apply_edit)
   - 더블클릭 편집(a19~a20) 제거. frameless 창의 easy_drag 가 mousedown 을 창 이동으로 먹어 dblclick 이 안 오는 경우가 많았고(곡천님: "클릭 자체가 안 될 때가 더 많았다"),
     자동 전송 ON 이면 '이미 송출됨' 으로 항상 거부됐으며, 딜만 고쳐도 킬을 0 으로 덮어썼다.
   - 새 방식: 합산 카드 우측 [🍗 치킨] [수정] 칩. 수정 패널은 인원수만큼 킬/피해량 입력칸, 비운 칸은 기존값 유지, [적용] / [적용 후 전송] / [취소] 만 커밋 (blur·Enter 커밋 없음).
   - 이미 송출된 결과도 수정 가능. [적용 후 전송] 은 수정된 값 메시지를 한 번 더 보낸다(2회 전송·수정 양식은 보류). 패널에 "이미 나간 값은 봇 쪽에서 따로 정리" 안내.
   - 기록에 edited / edited_from 저장 → 기록 탭 "수정됨 (이전→새값)" 태그.
   - 계산·F9·수정·치킨 토글 네 경로가 같은 _compose_result() 를 쓰도록 통합. 읽지 않은 대상에는 보너스를 더하지 않는다(킬 모드에서 {딜합계}="1000" 나가던 것 해결).

3-3. 전송 결과 반영 (_send_chat)
   - 예전: 스레드만 띄우고 즉시 "전송 완료" + sent=True. 실패는 errors.log 에만.
   - 지금: 전송 직렬화 락 + 최소 간격 1초, 성공 시에만 sent 표시, 실패 시 상태줄에 "전송 실패: 이유" 와 기록은 미송출(회색) 유지 → 재전송 가능.
   - ReadTimeout(요청은 갔는데 응답만 못 받음)은 재시도하지 않는다 — 재시도하면 같은 채팅이 두 번 나갈 수 있다. ConnectTimeout/ConnectionError 만 재시도.
   - F9 송출 시 기록의 message 도 송출 문구로 갱신(update_latest_message).

3-4. 스팀 모드
   - 대기열 경로도 steam_screenshot_delay 만큼 기다린 뒤 파일 크기 안정화(연속 2회 동일) 후 읽는다(_wait_file_stable). 예전엔 즉시 읽어 쓰는 중인 JPG 를 잡았다.
   - 대기열 항목에 감지 시각을 붙여 20초 지나면 버린다(지난 판 스샷으로 계산 방지).
   - 스캔 결과가 비면(폴더 일시 해제) 기준 스냅샷을 갱신하지 않는다(복구 시 전 파일이 '신규' 로 잡히던 문제).
   - HotkeyManager 에 F8/F9 개별 플래그. 스팀 모드 = F8 만 내리고 F9 유지. start() 가 이전 스레드를 join 한 뒤 재등록(빠른 토글 시 code=1409 고정 해소).

3-5. 보안·영속성
   - .gitignore: config.backup.json, *.json.tmp 추가. 올리기.bat 이 커밋 직전 스테이징 목록에서 config/token/history 파일을 찾으면 중단(:secretfound).
   - 토큰 저장: tmp + os.replace, _lock 안에서 교체. 읽기 실패 시 메모리 토큰 유지. get_config 가 매번 파일을 재로드하던 것 제거.
   - 리프레시 토큰이 4xx 로 거부되면 clear_tokens() → UI "미연결". 네트워크 오류는 보존.
   - 설정 모든 setter 가 즉시 저장(_persist). "설정 저장" 버튼은 유지.
   - 클릭 가드 5초 폴백: 브리지가 없어도 가드를 풀고 안내. 최초 실행 카드가 타이틀바를 덮지 않게(top:49px).
   - 올리기.bat 회귀 캡처 복사 원본: a27 → 없으면 a25 폴더. 괄호 블록 대신 goto 라벨(지연 확장 함정 회피).

[7] 잠재 함정
- _detect_rank_state 좌표는 1080p 정규화 기준 고정. 21:9 등 비율이 다른 화면은 resize 로 찌그러져 '#' 위치가 x28~42 범위를 벗어날 수 있다 → None(판정 불가) 으로 떨어져 수동 토글 안내가 뜬다(오판보다 안전).
- 치킨 재캡처는 화면 캡처 모드에서만. 스팀 모드는 파일이라 재캡처 불가 → None 이면 안내만.
- _send_chat 은 락 때문에 연속 전송이 1초 간격으로 직렬화된다. 자동 전송 + F9 동시 입력 시 두 번 나간다(의도: 사용자가 두 번 보낸 것).
- get_last_result 의 editable 은 "이번 실행에서 F8 을 한 번이라도 눌렀고 결과가 있다" 이다. 재시작 직후엔 수정 불가(세션 락 유지).
- expected_results.json 을 이번에 --update-baseline 으로 갱신했다(chicken 키 추가). PASS/FAIL 은 a25 와 동일.
