PUBG 스트리머 헬퍼 fix_a16 패치노트
=====================================

[버전 정리 안내]
fix_a16 = fix_a15.3 시점 코드와 동일.
fix_a15 본 패치 + a15.1/a15.2/a15.3 누적 안정성 패치를
정식 베타 진행 단위로 묶어 a16으로 리네임한 것.

곡천님 패키징 규칙(zip 파일명과 내부 폴더명 일치)에 맞춰
zip = pubg_streamer_helper_1_0_fix_a16.zip
폴더 = pubg_streamer_helper_1.0_fix_a16/

OCR 로직(스쿼드4 2/7 형태 검증, 결과창 진입 게이트)은 fix_a15 그대로.
회귀 테스트 baseline(스쿼드 52장 PASS)도 그대로 유효.

[누적 변경 요약 (a15 → a15.1 → a15.2 → a15.3 → a16)]
────────────────────────────────────────

A. fix_a15 본 패치 (OCR 정확도 + 게이트)
   1. _shape_bonus에 2/7 형태 검증 추가 (rows 17-19 받침 흰픽셀)
      - #12 P1딜 172 오인식 해결 (a14: 177 → a15: 172)
   2. score_result_screen 함수 + RESULT_SCREEN_MIN_SCORE = 0.085
   3. _calculate_impl 진입 게이트 (결과창 아닌 캡처 OCR 스킵)
   - 검증: 스쿼드 52장 100% (킬 200/200 + 딜 200/200 + INVALID 차단 2/2)
   - 회귀 테스트 도구 신설: tests/regression/ (52장 baseline 박제)

B. fix_a15.1 본 패치 (안정성 점검)
   1. F8 핫키 콜백 try/except (HotkeyManager._run, line 312)
      - 콜백 예외로 메시지 루프 죽어서 F8 영구 무력화되던 위험 차단
   2. OAuth 콜백 서버 포트 충돌 시 친절 메시지
   3. manual_send 예외 보호
   4. 시작 직후 응답없음 3중 방어
      4-1. UI 가드: pywebviewready + init() 완료 전 입력 차단
      4-2. 백그라운드 워밍업: mss/template strip 미리 호출
      4-3. 모니터 리스트 60초 캐싱

C. fix_a15.2 본 패치 (다른 PC 배포 안정화)
   Phase 1: 한글 경로 robust 강화
     - check_environment에 한글/특수문자 경로 사전 검출
     - browse_steam_dir의 PowerShell utf-8 명시
   Phase 2: DPI 스케일링 대응
     - _enable_dpi_awareness() main() 진입 직후 호출
     - Per-Monitor V2 → System → 폴백
   Phase 3: 환경 자가 진단 강화
     - WebApi 시작 시 진단 로깅 확장 (Python/Platform/모니터/DPI/설정 요약)
     - 첫 캡처 시점 frame 크기 진단 1회
   Phase 4: 사용안내.txt 추가

D. fix_a15.3 본 패치 (안정성 인프라)
   A. 메모리 사용량 30분 주기 자동 측정
      - config.memory_log_enabled / memory_log_interval_minutes
      - 누수 패턴 며칠 후 events.log로 즉시 감지
   B. 종료 시 cleanup 점검 (변경 없음, 메모리 스레드 정리만 추가)
   C. 로그 백업 카운트 5 → 7 (총 ~8MB)
   F. F8 핫키 등록 실패 시 UI 알림
      - HotkeyManager registration_failed 플래그 → poll_state → UI 상태바
   G. config.json 손상 복구 점검 (변경 없음, 기존 3중 fallback 견고)

[보류된 항목 (다음 채팅의 나에게: 왜 이번에 안 했는지 기록)]
────────────────────────────────────────

▼ 솔로/듀오 50장 회귀 검증
   왜 보류: 캡처 데이터셋 자체가 아직 없음.
            솔로 8장/듀오 10장은 작은 샘플이라 일반화 금지 원칙 위반.
   해제 조건: 곡천님이 솔로/듀오 게임 결과창 50장씩 모은 뒤 zip 전달.
   다음 작업: 시각 검수 → 정답 만들기 → fix_a16으로 OCR 측정
              → 100% 미만이면 fix_a17 패치 → 회귀 테스트로 안전 검증.

▼ 스쿼드3 OCR 정확도 0/6 (미해결)
   왜 보류: 캡처 1장 기반 임시반영 상태. 검증 데이터가 너무 적음.
            duo strip 재사용 중이라 글자 크기/색이 안 맞을 가능성 높음.
   해제 조건: 스쿼드3 캡처 50장+ 수집 후 본격 작업.
   현재 회피: 곡천님은 squad4 강제 사용 중이라 직접 영향 없음.
              다만 친구 PC 배포 시 squad3 게임하는 사용자에겐 OCR 안 됨.

▼ 자동 모드 감지 - squad4가 squad3로 감지되는 케이스 (47/49/50번)
   왜 보류: squad3 ROI가 squad4 ROI와 겹치는 영역 분리 작업이
            스쿼드3 본격 작업과 같이 가야 효율적. 캡처 모이면 같이 처리.
   현재 회피: 곡천님 squad4 강제 사용 → 영향 없음.

▼ QHD/4K 캡처 게이트 임계값 적정성
   왜 보류: QHD 캡처 데이터가 한 장도 없음.
            다운스케일로 흰픽셀 비율 달라질 수 있어 0.085 임계값이
            QHD에서 너무 빡빡하거나 너무 느슨할 가능성.
   해제 조건: QHD 캡처 수집 → 게이트 점수 분포 측정 → 임계값 조정.
   현재 회피: config.json result_screen_min_score 키로 사용자 조정 가능.
              QHD 사용자가 자주 차단되면 0.05 등으로 낮추라고 안내.

▼ 멀티 변형 voting (단일 자리 동점 케이스 자동 해결)
   왜 보류: a15에서 2/7 케이스를 _shape_bonus로 직접 해결했고,
            솔로/듀오 50장 검증 결과를 봐야 추가 voting 필요한지 판단 가능.
            솔로/듀오가 100%로 나오면 voting은 불필요.
   해제 조건: 솔로/듀오 검증 후 새로운 동점 케이스 발견 시.

▼ 유료 배포 키 인증
   왜 보류: 베타 안정화 단계라 시기상조.
            옵션(시리얼/서버 인증/하드웨어 잠금/구독) 검토는 별도 작업.
   해제 조건: 베타 충분히 안정 → 별도 채팅에서 옵션 비교.

▼ 알려진 트리비얼 이슈 (영향 거의 없음, 우선순위 낮음)
   - #5 save_config 동시성 문제 (실사용 거의 안 발생)
   - #7 chat_message_format default 불일치 (트리비얼)

[대화 맥락 / 곡천님과 합의된 방향]
────────────────────────────────────────

- 작은 샘플 일반화 금지: 솔로 8/듀오 10/스쿼드3 1장 같은 작은 샘플로
  "100% 됐다"고 보고 금지. 진짜 검증은 50장+ 단위.

- 보고 톤: 솔직한 한계 명시 우선. 자신만만한 보고 후 실전에서 깨지면
  곡천님 실망 큼. "현재 X/Y인데 Z 패턴이 깨질 수 있어요" 같이 우려 명시.

- 패키징 규칙 (절대 준수):
  1. 파일 수정 시 fix 번호 +1 (덮어쓰기 금지)
  2. zip 파일명과 내부 폴더명 일치
  3. 이전 버전 파일 같이 묶지 않기
  4. 파일 하나만 전달 (한 번에 여러 버전 X)
  예외: 회귀 테스트 도구처럼 분리 자연스러운 경우는 분리 가능.

- 패키징 전 필수 검수:
  · main.py와 ui/index.html 양쪽 반영 확인
  · JS 함수 존재 여부, HTML 이벤트 연결, 체크박스 disabled, init 초기화
  · .bat 파일들의 버전 표시 메시지도 새 버전으로 갱신

- 도구 대상: 곡천님 한 명을 위한 도구가 아닌 모든 PUBG 스트리머용.
  → 다양한 PC 환경/캐릭터 의상/글자 조합에 robust 필요.
  → FHD/QHD 모두 지원 필수.

- 패치노트 작성 규칙 (이 a16부터 적용):
  · 단순 변경 사항만 적지 말 것.
  · 보류 항목 + 왜 보류했는지 + 해제 조건 같이 기록.
  · 향후 우선순위 명시.
  · 대화 맥락 / 합의된 방향 기록.
  → 이유: 다음 채팅의 Claude가 읽고 바로 작업 이어갈 수 있게.
