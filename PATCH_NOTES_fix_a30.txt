PUBG 스트리머 헬퍼 1.0 fix_a30 — 패치 노트
작성일: 2026-08-20
=====================================================================

[1] 한 줄 요약
a29 실기에서 "모니터 목록 비어 있음 + 설정 버튼 전부 먹통 + 창이 귀신 들린 듯 느리게 따라옴, 재시작하면 정상" 이 나왔다(영상·로그 확보).
세 증상은 하나다: JS→파이썬 브리지가 그 실행에서 늦게 붙었거나 막혔다. 창 이동(easy_drag)도 브리지를 타므로 같이 느렸다.
a30: ① 창 드래그를 Windows 네이티브로(브리지 호출 1회) ② DWM 둥근 모서리 훅을 before_show→shown ③ 브리지 감시(실패 시 2초 간격 재시도 + 로그).
OCR·전송 로직 무변경, 회귀 52/52.

[2] 근거
- events.log(22:42:16 실행): 시작 로그는 전부 정상, errors.log 비어 있음 → 파이썬 쪽 예외 없음. 그런데 UI 는 get_config 결과를 못 받음(모니터 select 비어 있음 = init 의 첫 호출이 null).
- 영상: 커서가 한참 앞서가고 창이 뒤늦게 따라옴 = easy_drag 의 mousemove 마다 JS→파이썬 move 호출이 줄을 섬.
- 이 패턴은 a17 부터 있던 "드래그 freeze" 와 같은 뿌리(v5 진단). 이번에 처음으로 영상+로그로 확인됐다.
- 재시작하면 정상 = 코드 결함이 아니라 실행마다 달라지는 초기화 타이밍 문제. 그래서 "원인 제거" 가 아니라 "브리지에 기대지 않기 + 늦게 붙어도 복구" 로 간다.

[3] 바꾼 것
- main.py create_window: easy_drag=False. WebApi.begin_native_drag(): ReleaseCapture + SendMessage(WM_NCLBUTTONDOWN, HTCAPTION) 를 별도 스레드에서 → Windows 가 창을 직접 끈다.
- ui/index.html: 타이틀바(#titlebar) mousedown(버튼 제외) → py('begin_native_drag') 1회.
- _apply_windows_rounded_corners 를 window.events.shown 에서 호출 (before_show 에서 제거).
- JS bridgeWatchdog: init 의 get_config 가 null 이거나 예외면 2초마다 최대 15회 재시도, 상태줄에 "백엔드 연결 중... (n)". 성공 시 events.log 에 "[a30] init OK: bridge ready after N ms" 가 남는다 → 다음에 같은 증상이 나면 이 숫자로 브리지 지연을 수치로 본다.

[4] 미검증 / 확인 부탁
- 네이티브 드래그가 WebView2 위에서 먹는지(타이틀바를 끌 때 창이 즉시 따라오는지). 안 되면 SendMessage → PostMessage 또는 ReleaseCapture 위치 조정이 다음 시도.
- 증상 재발 시: events.log 에 "[a30] bridge watchdog retry" 줄이 몇 번 찍혔는지, "init OK ... ms" 값.
- a29 마이그레이션 로그에 chat_tokens.json 이 없었다(config/backup/history 만 복사). a27 설치판에서 치지직 연결을 했다면 토큰 파일이 exe 옆에 있었어야 한다 → 연결 상태가 유지됐는지 확인 필요. 안 됐으면 설정에서 다시 연결(1회).

[5] 잠재 함정
- easy_drag=False 라 타이틀바 외 영역은 더 이상 끌리지 않는다(의도).
- CSS 의 -webkit-app-region:drag 는 WebView2 에서 효과 없음(남겨둠, 무해).
- 네이티브 드래그 스레드는 드래그가 끝날 때까지 SendMessage 에 머문다(데몬 스레드, 한 번에 하나).
