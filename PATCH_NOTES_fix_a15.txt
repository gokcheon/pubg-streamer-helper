PUBG 스트리머 헬퍼 fix_a15 패치노트
=====================================

[메인 목표]
실전 50장+ 검증에서 발견된 fix_a14의 두 가지 헛점 보완:
  1. 단일 자리 점수 동점 시 "큰 숫자 우선" 정렬로 인한 2/7 오인식
  2. 결과창이 아닌 캡처에서도 OCR이 강제 진행되어 garbage 결과 출력

[배경]
fix_a14 배포 후 곡천님이 수집한 스쿼드 50장+ 캡처(총 52장)로 검증.
시각 검수 결과 vs a14 OCR 비교에서:
  - 킬 200/200 (100%) - 안정적
  - 딜 199/200 (99.5%) - 1건 오인식 (12번 P1 딜: 172→177)
  - 결과창 아닌 캡처 2장 (41번, 43번)에서 9999 등 garbage 출력
  - 종합 99.75%

[발견된 두 가지 문제]

1. 12번 P1 딜 마지막 자리 2 → 7 오인식
   원인: _digit_options() 정렬 키가 (score, digit != "1", digit)
        점수 동점일 때 큰 숫자 우선 → 7이 2를 이김
   실측 (12번 P1 딜 마지막 자리 candidate 영역):
     - 하단 3 row 흰픽셀: r17=4, r18=10, r19=10, sum=24
     - 2 템플릿: r17=11, r18=11, r19=11, sum=33 (받침 꽉 참)
     - 7 템플릿: r17=3, r18=3, r19=4, sum=10 (받침 빈약)
     → candidate는 명확히 2의 패턴이지만 매칭 점수 산정에서 동점 발생
   해결: _shape_bonus()에 2/7 자리 무관 형태 검증 추가

2. 결과창이 아닌 캡처에서 OCR 강제 진행
   원인: detect_game_mode()가 무조건 best_mode를 반환 (게이트 없음)
        호출부에서도 mode 검증만 하고 "결과창인지 아닌지"는 체크 안 함
   실측 (best_score 분포):
     - 정상 결과창 50장: min=0.1008, max=0.2780
     - 결과창 아님 (다음 페이지) 2장: 0.0490, 0.0669
     - 마진: 0.0669 ↔ 0.1008 = 0.034 차이
   해결: score_result_screen() 함수 추가 + 호출부에 진입 게이트

[변경 사항]

1. _shape_bonus 함수에 2/7 형태 검증 추가 (main.py 1295번 줄 근처)
   영역: rows 17-19 (하단 3 row) 흰픽셀 합산
   - "2" 후보: bottom_3rows >= 18 → +0.06, <= 12 → -0.10
   - "7" 후보: bottom_3rows >= 18 → -0.10, <= 12 → +0.06
   참고: 동일한 결의 shape_bonus는 fix_a14의 0/6/8/9, 6/9, 6/8, 5/6, 9/3 분리에 이미 사용됨

2. score_result_screen 함수 추가 (main.py 1727번 줄 근처)
   detect_game_mode와 동일 측정 기준이지만 (mode, score) 튜플 반환
   기존 detect_game_mode는 그대로 유지 (backward compat)
   상수 RESULT_SCREEN_MIN_SCORE = 0.085 추가
   (invalid 최대 0.0669, valid 최소 0.1008 사이의 안전 마진)

3. _calculate_impl에 결과창 진입 게이트 적용 (main.py 2334번 줄 근처)
   - auto/manual 모드 모두 적용 (수동 squad4 고정 사용자도 보호)
   - score_result_screen으로 best_score 계산
   - score < threshold 면 OCR 스킵하고
     "결과창이 아닌 화면으로 판단됨 (점수 X.XXX < Y.YYY)" 에러 반환
   - config.json으로 비활성화 가능:
     - "result_screen_gate_enabled": false  → 게이트 비활성화
     - "result_screen_min_score": 0.085     → 임계값 조정
   - event_logger에 차단 사유 기록
