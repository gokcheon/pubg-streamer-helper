[1] 한 줄 요약
채팅 메시지를 한 줄 더 보낼 수 있게 했다(메시지 2, 켜기/끄기). 읽기 대상에 "딜+킬" 을 추가했고, 전송 여부를 줄마다 따로 기록해서
실패한 줄·수정으로 문장이 바뀐 줄만 다시 보낸다. a33 의 "응답없음" 진단 코드는 그대로 들어 있다.

[2] 큰 그림 — 프로젝트의 현재 위치와 핵심 원칙
- 앱: PUBG 결과 화면을 OCR 로 읽어 치지직 채팅에 보내는 도구. 파이썬 백엔드(main.py 단일 파일) + pywebview(WebView2) 화면(ui/index.html).
- 이 기능의 목적(곡천님): 명령어로 딜을 차감하고 킬도 차감하려면 명령어 두 줄이 연달아 나가야 한다.
- 진행 중인 다른 일: 실행 시 "응답없음" 버그. a33 에서 진단 기록(logs/startup_trace.log)을 넣었고, 멈춘 실행이 한 번 기록되면 그 위치를 보고 고친다.
- 원칙: 화면 변경은 "말로 확인 → 시안 이미지 → 승인 → 구현" 순서. a34 승인 근거: 곡천님 발언 「0.3초 확정」 (2026-11-18, 시안 6장 + 동작 6개 항목 + 줄 간격 값).
- 원칙: 한 번에 한 층. 메시지 2(a34) 와 "취소 명령어 → 수정값 전송"(아이디어 단계) 은 분리해서 만든다.

[3] 이번 fix 의 핵심 결정과 이유 (전부 곡천님 확정)
3-1. 메시지 2 를 켜면 딜과 킬을 자동으로 둘 다 읽는다 (읽기 대상이 "딜+킬" 로 고정).
   - 이유: 메시지 2 를 켜고 읽기 대상을 "딜량" 으로 두면 {킬합계} 가 0 으로 나가는 실수가 생긴다.
   - 끄면 사용자가 골라 둔 읽기 대상으로 돌아간다 (config 의 read_target 값은 지우지 않는다).
3-2. 읽기 대상 선택에 "딜+킬" 추가.
   - 이유(곡천님): 한 줄 명령어에 {킬합계} 와 {딜합계} 를 같이 쓰는 사용자가 생길 수 있다.
3-3. 줄마다 전송 여부를 따로 기록하고, 재전송은 실패한 줄만.
   - 이유: 성공한 줄을 또 보내면 미션 봇이 두 번 차감한다.
3-4. [수정] 후 전송은 수정 전과 문장이 달라진 줄만.
   - 딜만 고치면 메시지 1 만, 킬만 고치면 메시지 2 만. 한 줄에 둘 다 쓴 경우에는 둘 중 하나만 고쳐도 그 줄이 나간다.
3-5. 메시지 1 과 메시지 2 사이 간격 0.3초 (SEND_LINE_INTERVAL).
   - 처음 제안은 기존 보호 간격 1초 재사용 → 곡천님 "1초 간격 좀 긴데" → 0 / 0.3 / 0.5 중 0.3 확정.
   - 서로 다른 전송 작업 사이의 1초(SEND_MIN_INTERVAL, a28) 는 그대로.
   - 치지직 공식 문서(chzzk.gitbook.io/chzzk/chzzk-api/chat)에는 전송 간격 제한이 적혀 있지 않다(메시지 최대 100자만). 실제 허용 간격은 미확인.
3-6. 메시지 1 이 실패해도 메시지 2 는 보낸다 (서로 다른 명령어).
3-7. 메시지 2 가 켜져 있어도 칸이 비어 있으면 그 줄은 보내지 않는다.
3-8. 두 줄이 모두 나간 기록의 [재전송], 전부 나간 결과의 F9 는 예전처럼 전체를 다시 보낸다.
3-9. {합계} 는 딜+킬일 때 딜량 합계.
기각한 것
   - 읽기 대상을 사용자가 직접 "딜+킬" 로 맞추게만 하기(자동 고정 없음): 3-1 의 실수 가능성 때문에 기각. 대신 선택 항목도 같이 넣었다(3-2).
   - 재전송 시 두 줄 모두 다시 보내기: 이중 차감 때문에 기각.

[4] 만든 것
main.py
   - 설정 키 2개: chat_message_format2(문자열, 기본 ""), chat_message2_enabled(참/거짓, 기본 거짓). config.default.json 에도 추가.
   - _effective_read_target(): 메시지 2 가 켜져 있으면 "both", 아니면 read_target. 계산(_calculate_impl)이 이 값을 쓴다.
   - _last_read_target: 가장 최근 계산이 실제로 읽은 대상. F9·수정·치킨 토글의 재계산은 이 값을 쓴다
     (딜만 읽은 결과 뒤에 메시지 2 를 켜도 그 결과에는 킬 줄이 붙지 않는다 → "킬 0" 이 나가는 것 방지).
   - _compose_result(): "lines" = [(slot, 문장)] 을 같이 돌려준다. slot 1 = 메시지 1, slot 2 = 메시지 2. "message" 는 줄바꿈으로 이은 문자열(overlay.txt 용).
   - HistoryManager: 항목에 "messages" = [{slot, text, sent}] 추가. 항목의 sent 는 "모든 줄이 나갔는가".
     _lines_of / get_lines / set_lines / mark_line_sent / latest_id 신설. update_latest 에 lines 인자.
     set_lines·update_latest 는 같은 slot 의 문장이 그대로면 전송 상태를 유지하고, 달라진 줄은 미송출로 돌린다.
     a33 이하에서 만든 기록(messages 없음)은 읽을 때 한 줄짜리로 바꿔서 보여 준다. history.json 을 따로 변환하지 않는다.
   - _send_chat 삭제 → _send_lines(줄 순서대로 전송, 줄별 표시, 상태 문구) + _start_send(전송 스레드 시작).
     전송 대상은 전송 잠금을 잡은 뒤에 다시 읽는다 → 자동 전송 중에 F9 를 눌러도 같은 줄이 두 번 나가지 않는다(예전에는 1초 간격으로 두 번 나갔다).
   - 전송 경로 4곳을 _start_send 로 통일: dispatch_auto_send(자동), manual_send(F9·버튼), resend_history(기록 탭), apply_edit(send=True).
   - set_read_target 이 "both" 허용. set_chat_message_format2 / set_chat_message2_enabled 신설. get_config 에 새 키 2개.
   - get_last_result: read_target 을 "마지막으로 실제 읽은 대상" 으로, sent_any·line_count 추가.
ui/index.html (시안 6장 그대로)
   - 설정: 읽기 대상에 "딜+킬". 메시지 2 가 켜져 있으면 선택이 잠기고 "메시지 2가 켜져 있어 딜과 킬을 둘 다 읽어요." 표시.
   - 설정 > 채팅 메시지: "메시지 1" 칸, "메시지 2 사용" 체크박스, "메시지 2" 칸(꺼져 있으면 흐리게·입력 잠금), 넣을 수 있는 값 안내.
   - 메인: 딜+킬 결과면 칸마다 딜량 옆에 보라색 "N킬", 합산 카드도 같음. 보너스·배수 적용 값은 "=딜 · N킬".
   - 기록: 일부만 나간 기록은 노란색 "일부". 두 줄 기록은 펼치면 줄마다 문장과 송출 상태. 버튼은 일부일 때 [남은 줄 전송].
   - 수정 패널 안내 문구: 딜+킬 모드 설명, "고친 값이 들어간 줄만 한 번 더 나가요".
상태 줄 문구
   - 한 줄: 예전과 동일("자동 전송 완료" 등). 두 줄: "✅ 채팅 2줄 자동 전송 완료".
   - 일부 실패: "⚠️ 메시지 1 전송됨 · 메시지 2 실패 — 기록 탭에서 [남은 줄 전송]".
   - 수정했지만 문장이 그대로: "바뀐 줄이 없어 전송하지 않았어요". 요청 뒤 다른 전송이 먼저 끝남: "이미 전송된 결과예요".
버전·표기: version.py APP_FIX=34, installer.iss 1.0.34, 올리기.bat 회귀 캡처 복사 경로 a33→a32 순, run_app/build_exe/package_dist 표기 fix_a34.

[5] 동작 범위
되는 것
   - 메시지 2 끔: 화면·전송 모두 a33 과 같다(한 줄). 달라진 점 하나: 자동 전송 중 F9 를 겹쳐 눌러도 중복 전송되지 않는다.
   - 메시지 2 켬: 한 판에 메시지 1 → 0.3초 → 메시지 2. 자동 전송·F9·설정 탭 버튼 모두 같다.
   - 읽기 대상 "딜+킬" + 메시지 1 한 줄에 {딜합계} {킬합계} 같이 쓰기.
   - 치킨 보너스·배수는 딜과 킬에 각각 적용(예: 딜 (1,254+1,000)×2 = 4,508 / 킬 (7+10)×2 = 34).
안 되는 것 / 주의
   - 취소 명령어를 먼저 보내고 수정값을 보내는 기능은 없다(아이디어 단계). 이미 나간 틀린 값은 봇 쪽에서 따로 정리해야 한다.
   - 줄 사이 0.3초가 치지직·미션 봇에서 항상 받아들여지는지는 실사용 확인 전이다. 거부되면 기록에 "일부" 로 남고 [남은 줄 전송] 으로 보낸다.
   - 메시지 2 를 켠 뒤의 결과부터 두 줄이 된다. 켜기 전에 읽은 결과(딜만 읽음)에는 킬 줄이 붙지 않는다.

[10] 다음 세션 Claude 를 위한 안내
- 전송 관련 코드는 _start_send → _send_lines 한 경로다. 새 전송 종류를 넣을 때 chat_client.send_message 를 직접 부르지 말 것(줄별 기록이 어긋난다).
- "어떤 줄을 보낼지" 는 history 의 messages[].sent 로만 정한다. 문장이 바뀌면 set_lines/update_latest 가 그 줄을 미송출로 돌린다.
- 취소 명령어 기능을 만들 때: 줄 상태가 "미송출/송출됨" 두 가지뿐이다. "취소됨, 수정값 미송출" 상태가 추가로 필요하다(곡천님께 제안한 3번).
- 곡천님에게 "차액 1회 전송" 을 다시 제안하지 말 것(기각됨).
- 시험 방법: main.py 는 리눅스에서도 import 된다(mss 만 가짜 모듈로 대체). WebApi() 를 만들고 chat_client 를 가짜로 바꾸면 전송 흐름을 그대로 시험할 수 있다.
  화면은 Playwright 의 expose_function 으로 window.pywebview.api 를 실제 WebApi 에 연결해 시험했다.
- 작업 공간(클라우드)은 오래 쉬면 초기화된다. 소스는 연결 폴더 D:\코딩\배그 딜량 체크\pubg_streamer_helper_1.0_fix_aNN\ 에서 가져온다.
- 보고 형식: 문제 원인 → 해결 방법 → 결과 → 내가 해야할 것. 해요체, 호칭 "곡천님". 파일 제작 전 시안·설계안 승인 필수(승인 발언 인용).
- 패키징 규칙: fix 번호 +1, zip 이름 = 내부 폴더명(영문), 이전 버전 미포함, __pycache__ 제외, .bat/.iss/.txt 는 UTF-8 BOM + CRLF,
  requirements.txt 는 CRLF·BOM 없음, 회귀 캡처 png 는 zip 에서 제외(30MB 제한).
