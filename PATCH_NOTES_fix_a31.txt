[1] 한 줄 요약
a30에서 창이 전혀 안 움직이던 회귀 수정 + 플레이어 칸(P1~P4) 클릭으로 수정 패널 열기. 변경 파일은 ui/index.html 하나뿐,
파이썬 코드 무변경(버전 번호·설치마법사 AppVer·올리기.bat 캡처 복사 경로만 a31 기준으로 갱신). OCR 무변경, 회귀 52/52.

[2] 핵심 결정과 이유

2-1. 타이틀바 .tb 의 -webkit-app-region 값을 drag → no-drag
   - 증상: a29 → a30 업데이트 직후 타이틀바를 끌어도 창이 안 움직임. 버튼·브리지는 정상.
   - 원인(다른 대화에서 확정): a17 때 들어간 `-webkit-app-region:drag` 가 .tb 에 남아 있었다. 이 값이 붙은 영역은 WebView2 가 마우스 이벤트를
     먼저 가져가므로 a30 이 새로 넣은 mousedown → py('begin_native_drag') 핸들러까지 신호가 안 갔다. a29 까지는 easy_drag 가 창을 옮겨서
     가려져 있었고, a30 에서 easy_drag 를 끄면서 이동 수단이 0개가 됐다. events.log 에 드래그 기록이 한 줄도 없던 것과 일치.
   - 기각: easy_drag 재활성화(a29 의 느린 추적 재발), 윈도우 기본 테두리 창으로 전환(상단바 디자인 상실).
   - 진단 로그 추가: mousedown 시 py('log_debug', '[a31] titlebar mousedown → begin_native_drag 호출'). 드래그 정상 확인되면 다음 버전에서 제거.

2-2. 플레이어 칸 클릭 → 수정 패널
   - "칸을 눌러도 수정이 안 된다"는 버그가 아니라 a28 설계 변경(더블클릭 편집 제거, [수정] 버튼+패널로 통일)의 결과였다.
   - 채택: 칸을 한 번 클릭하면 기존 수정 패널이 열리고 그 칸의 입력란에 커서가 간다(openEdit(focusIdx)). 편집 경로는 여전히 패널 하나.
   - 기각: 더블클릭 복원(a28 이전 문제 재발), 칸 인라인 편집(편집 경로 두 갈래).
   - setCardsEditable(ok, count): 수정 가능 상태 + 인원수 안쪽 칸에만 editable 클래스(손모양 커서, 테두리 강조, 툴팁). renderResult / refreshEditAvailability 에서 호출.
